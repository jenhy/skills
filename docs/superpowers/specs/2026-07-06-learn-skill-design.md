# Learn Skill — 10x 学习加速器

**日期**: 2026-07-06  
**作者**: ross  
**类型**: Skill 设计文档

## 概述

`learn` 是一个 Claude Code skill（`disable-model-invocation: true`），帮用户以 10 倍速度学习任何主题。它是现有 `teach` skill 的**超集**——完整内联 teach 的教学工作空间，再叠加 6 个学习加速工具。

## 与 teach 的关系

`learn` 不引用 `teach`（零外部依赖），而是将 teach 的工作空间逻辑直接内联进自己的 SKILL.md。即使 `teach` 被卸载，`learn` 仍完整运作。

**teach 管"怎么教"，learn 管"怎么学得更快"。**

learn 完整继承 teach 的工作空间结构：

```
工作空间/
├── MISSION.md              # 学习目标 + 学习阶梯表
├── RESOURCES.md            # 筛选后的高价值资源
├── NOTES.md                # 用户偏好和计划记录
├── lessons/*.html          # 课程文件
├── reference/*.html        # 参考资料（含速查表）
├── learning-records/*.md   # 学习记录
└── assets/*                # 复用组件
```

## 架构：6 工具串联工作流

```
路由: A(新手) / B(有基础) / C(项目驱动)
  │
  ▼
[1] 学习阶梯 —— 5 级地图，确认起点和目标
  │ 产出：阶梯表 → MISSION.md
  ▼
[2] 信号筛选 —— 筛 N 个最优资源 + M 天学习路径
  │ 产出：资源列表 → RESOURCES.md，学习路径 → MISSION.md
  ▼
[3] 20 小时学习法 —— 80/20 核心提取，拆成 X 次 × Y 小时计划
  │ 产出：每次计划详情 → NOTES.md
  ▼
[4] 费曼检验 —— 每节课后，对 12 岁小孩讲清楚，诊断漏洞
  │ 产出：诊断报告 → learning-records/
  ▼
[5] AI 考官 —— 关键节点考试，渐进难度，低于 M 分需回补
  │ 产出：考试成绩 + 精准复习引用 → learning-records/
  ▼
[6] 一页速查表 —— 按使用场景定制，可打印 HTML
  │ 产出：速查表 → reference/<主题>-cheatsheet.html
```

## 工具 1：学习阶梯

**目的**：画出领域全景地图，定位用户起点和目标。

**交互模式：严格的一问一答采访。每次只问一个问题，等用户回答后再继续。禁止一次性输出多个问题或所有级别阶梯。级数由 Claude 根据主题大小决定（不固定，但不能少于覆盖核心 20% 知识所需的级数）。**

**路由问题**（只问这一句）：
> "关于 [主题]，你是：A. 完全新手，连名词都不熟 / B. 看过一些，但没正经做过 / C. 做过东西，想系统提升"

**三条支线**（必问问题四个不少，顺序因路由而异）：

| 支线 | 流程（每步一问，等回答后再继续） |
|------|------|
| A（新手） | ①确认边界 → ②逐级展示全景（一次一级，每级讲完问"这层有没有想深入了解的？"）→ ③问位置 → ④问目标 → ⑤确认路径 |
| B（有基础） | ①摸底 → ②确认位置 → ③问目标 → ④定制阶梯（一次一级，逐级展示）→ ⑤确认路径 |
| C（项目驱动） | ①问终点场景 → ②反推目标等级 → ③确认位置 → ④定制阶梯（一次一级，逐级展示）→ ⑤确认路径 |

**关键约束**：
- 级数由 Claude 根据主题大小决定，不固定为 5 级，但不能少于覆盖核心 20% 知识所需的级数
- 逐级展示阶梯时，一次只展示一级，展示完必须停顿等用户回应
- 每级展示后问"这层有没有想深入了解的？"——有则展开，无则继续
- 禁止一次性输出所有级别

**必问问题（已嵌入各支线步骤中）**：
- 当前在哪个层次？
- 每一层应该掌握什么？
- 常见错误是什么？
- 达到什么标准才能进入下一层？

**产出**：阶梯表写入 `MISSION.md` 第二段，作为后续所有工具的目标锚点。

## 工具 2：信号筛选

**目的**：从海量材料中只保留最值得看的，节省时间。

**交互模式：一问一答。每次只问一个问题，等用户回答后再继续。**

1. **学习方式偏好**（一问）：视频 / 文档 / 动手做 / 书 / 都可以。等回答。
2. **语言偏好**（一问）：中/英/都可以。等回答。
3. **资源筛选**：Claude 自行决定 N 个资源（N 非固定），每个资源说明：是什么、适合谁、难度、怎么用、**别看哪里**。列完后等用户确认。
4. **M 天学习路径**（M 非固定）：每天看什么 + 练什么 + 产出什么。列完后等用户确认。

**产出**：N 个资源写入 `RESOURCES.md`，M 天路径写入 `MISSION.md`。

---

## 工具 3：20 小时学习法（80/20 法则）

**目的**：提炼核心 20% 内容，排成精确到每次的实战计划。

注："20 小时"指 Josh Kaufman 的快速学习理论，实际总时长由 Claude 根据主题大小和阶梯跨度建议，用户确认或调整，非固定值。

**交互模式：每个决策点 Claude 给 2-3 个选项 → 建议一个 → 等用户确认或调整。每次只处理一个决策点。**

1. **时间投入**（一问）：Claude 列出 2-3 个可选总时长，建议一个 → 等用户确认
2. **80/20 提炼**（一问）：Claude 解释为什么这 20% 能带来 80% 效果 → 等用户确认
3. **拆计划**：分成 X 次 × Y 小时（X、Y 非固定），每次对应一节 lesson。**对每次 session 的 4 个要素逐个处理，一次只处理一个要素：**
   - 学什么 — 2-3 种方案 → 建议一种 → 等确认
   - 练习什么 — 2-3 种方案 → 建议一种 → 等确认
   - 用哪些资源 — 2-3 种搭配 → 建议一种 → 等确认
   - 复盘什么 — N 个问题，2-3 组 → 建议一组 → 等确认
   - 一个 session 确认完后，再进入下一个 session。禁止一次性列出所有 session。
4. **整体确认**（一问）：展示汇总 → 等用户最终确认

**产出**：每次计划详情写入 `NOTES.md`，后续费曼检验和 AI 考官以这些 session 为时间节点。

## 工具 4：费曼检验

**目的**：逼用户用自己的话讲清概念，暴露"以为懂了"的幻觉。

**交互模式：一问一答。每次 Claude 只做一件事，等用户回答后再继续。**

1. Claude 指定上节课学的概念，要求用户对 12 岁小孩讲一遍。等用户讲完。
2. Claude 给出诊断：讲对了什么、漏了什么、混淆了什么、哪些词用了但没真懂。
3. Claude 只重新解释没掌握的部分。等用户再讲。
4. 迭代直到完全讲清（最多 N 轮）。

**产出**：诊断报告写入 `learning-records/`（如 `0003-feynman-<概念>.md`）。

---

## 工具 5：AI 考官

**目的**：渐进式压力测试，从简单到困难，定位知识盲区。

**交互模式：一问一答。一次只出一道题，等用户答完并收到反馈后，再出下一题。禁止一次性出多道题。**

1. **时机选择（路由，一问）**：Claude 先分析 session 间的知识边界，给出建议节点，然后提供 A/B/C 选项 → 等用户选择
2. **出题规则**：
   - 必须覆盖 20% 最核心知识
   - 混合主观题 + 客观题，题数 N 由 Claude 决定
   - 难度渐进：知识记忆 → 理解原理 → 场景应用 → 批判发散
3. **考试流程（一次一题）**：出题 → 等回答 → 给得分/诊断/只解释没掌握的 → 出下一题
4. **判定**：N 题答完，总平均分 < M 分（M 默认 6）→ 不通过
5. **综合评估**：扎实的部分 + **需要补的部分必须给出具体 lesson HTML 路径 + 章节引用**

**产出**：考试成绩 + 评估写入 `learning-records/`（如 `0004-exam-<阶段>.md`）。

---

## 工具 6：一页速查表

**目的**：把整个主题压缩到一页可打印 HTML，按使用场景定制。

**交互**：

1. **路由（使用场景）**：
   - A. 面试突击 — 常见题、一句话回答、易被追问的坑
   - B. 考前复习 — 公式/语法速查、题型模板、易混概念对比
   - C. 演讲/分享 — 叙事逻辑线、关键数据/案例、金句
   - D. 日常查阅 — API/命令速查、代码片段、检查清单
   - E. 教别人 — 类比解释、概念关系图、循序理解路径
   - F. 项目实战 — 最佳实践、常见错误、项目模板
2. Claude 生成第一版 HTML，用户反馈，定稿

**产出**：`reference/<主题>-cheatsheet.html`，美观可打印。

## 内联内容

### teach 工作空间

完整内联 teach 的工作空间管理逻辑，包括：
- `MISSION.md`、`RESOURCES.md`、`NOTES.md` 的格式和用途
- `lessons/*.html` 的课程生成逻辑（知识 + 技能 + 反馈循环）
- `reference/*.html` 的参考文档生成
- `learning-records/*.md` 的学习记录格式（类似 ADR）
- `assets/*` 的复用组件管理
- 流畅度 vs 存储强度的学习理论
- 最近发展区（ZPD）定位

### 前端设计精简标准

内联约 150 字的前端设计标准，用于 lesson HTML 和速查表的视觉质量：
- 不落入三种 AI 模板配色（奶油暖色 / 黑底荧光 / 报纸栏式）
- 配色 4-6 个命名 hex、字体 2+ 角色、布局概念一句话
- 一个记忆点（signature element），其余克制
- 响应式移动端、可见键盘焦点、尊重 reduced motion

## 交互原则

**核心原则：一问一答采访模式。** 工具 1-5 的每个步骤都是一个单独的问题或动作，Claude 必须等用户回应后再继续下一步。禁止一次性输出多个问题、多个步骤、或全部内容。

每个决策点遵循：**Claude 给选项 → 建议一个 → 等用户确认或调整**。不做拍脑袋决定，不填大表格，不搞信息轰炸。
